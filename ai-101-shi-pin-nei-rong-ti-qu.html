提示、RAG、微调怎么选？

第 7 章的取舍表 — 选择依据是准确性、新鲜度、成本、延迟与维护难度，不是哪一种永远最好。

方法什么时候用擅长不擅长 / 注意
提示 Prompting任务清晰、所需信息能直接提供时先用它快、便宜、无需训练补不上系统没有的知识
RAG答案依赖私有、细节多或频繁更新的信息信息新鲜、更新文档比再训练简单不能消除幻觉，可能取错段落
微调 Fine-tuning教一致的风格、格式或重复任务模式输出风格稳定不适合自动添加易变事实

三者可以组合使用。

术语速查

Token 词元模型处理文本的基本单位，影响容量、时间与成本
Embedding 嵌入把文本变成向量，意思相近则距离更近
Context Window 上下文窗口单次请求能处理的信息量上限
Hallucination 幻觉听起来合理、却缺乏事实依据的回答
HNSW / IVF两种近似最近邻索引：图结构 / 分簇搜索
ANN · Recall近似最近邻搜索 · 召回率，速度与召回要权衡
RAG · Reranking检索增强生成 · 对候选块重排
ReAct推理与行动交替进行的 Agent 模式
Human-in-the-Loop重要动作前停下来等人批准
MCP连接 AI 应用与工具 / 上下文的开放协议
Guardrails 护栏校验、审核、权限限制等多层检查
Prompt Injection不受信任内容里藏操纵模型的指令
Evals 评估用代表性案例检验系统是否按预期表现
Context Engineering选择、组织与更新模型收到的全部信息
RLHF用人类对回答的比较来训练 / 优化模型
Episodic / Semantic Memory情景记忆（过去事件）/ 语义记忆（稳定事实）
AI Gateway应用向模型发请求的网关层
Observability 可观测性监控、追踪系统行为与故障

学习清单

看完视频后，用这 6 步自测是否真的理解了。

  1. 先能用自己的话讲清词元、嵌入、上下文窗口与幻觉，再看 RAG 流程图。
  2. 用客服助手例子走一遍：检索 → 重排 → 生成 → 校验 → 建单 → 失败降级。
  3. 对比提示、RAG、微调在准确性、新鲜度、成本、延迟、维护上的取舍，写出各自适用的三个场景。
  4. 画出一个单 Agent 循环（目标 → 推理 → 工具 → 观察 → 停止条件），标出超时、重试上限与人工确认点。
  5. 列出 MCP 连接里必须回答的安全问题：信任哪些服务器、工具能看什么数据、哪些动作要批准。
  6. 为一个假设的客服助手写 10 条评估用例，覆盖取对文档、忠于来源、缺答案时拒绝、工具失败时不编造。
