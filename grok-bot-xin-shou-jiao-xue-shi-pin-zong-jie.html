01

Grok Bot 是什么

约 0:00 起

先立概念：Grok Bot 不是「更聪明的聊天框」，而是「一队 AI 员工」。和 Claude Code、Codex 拉开差距的，是运行环境——它们跑在你的电脑上，Grok Bot 的 bot 跑在云端电脑上。

  • 对 ChatGPT：从「问答」变「交付」——你交代的是任务，它回的是结果。
  • 对 Claude Code / Codex：能力相近，但它们依赖本地电脑开机；Grok Bot 的云端电脑全天在线，还能存账号登录状态，任务不用等你回到电脑前。
  • 对开源方案：省掉买设备、租服务器、自己部署维护这一整套门槛。
02

第一只 bot

约 3:30 起

从下载安装进入主画面后，直接上手建第一只 bot。视频里的示例包括设计负责人 Chief of Design、London Chief of Staff（伦敦幕僚长）等——命名方式就是「职位」，你管理的是一支队伍，不是一个个对话框。

这一章的操作要点

  • 在对话里直接给 bot 派任务，它会像员工一样先确认「先帮你处理哪一摊」，再动手。
  • 每只 bot 右侧有三个页签：Details（设定）、Library（资料）、Computer（它的云端电脑）。
  • bot 多了以后，右键可以分组、置顶，先把最常用的放前面。
03

打造 AI 团队

约 7:30 起

单只 bot 之上再加一层组织：设一位幕僚长（Chief of Staff）当总管，由它带一队专职 bot——比如专门盯美股情报的「美股情报员」。你只对幕僚长交代目标，它负责拆解、分派、汇总，是全片最核心的用法。

一只专职 bot 怎么配齐

  • Context：给它岗位说明书和长期记忆——它是谁、负责什么、记住哪些背景。
  • Integrations（外挂接入）：连上 Gmail、Google Calendar 等外部服务，它才能读你的邮件和日程干活。
  • Routines：给它排班，固定时间自己开工（下一章细讲）。
  • 组织上用两层结构：幕僚长 → 专职 bot。你管一个人，它管一队人。
04

专属云端电脑

约 13:00 起

每只 bot 都有一台专属云端电脑：笔记本合上、手机锁屏，bot 还在云端继续跑。这一章还讲了分工搭配——日常杂事和随时交办用 Grok Bot，写代码、开 PR 这类活交给 Claude Code / Codex，两边拼成一条完整工作流。

  • Grok Bot 这一侧：入口在手机上，随时随地派活，适合日常、通用、持续性的任务。
  • Claude Code / Codex 这一侧：守着代码仓库，负责写程序、开 PR 等开发工作。
  • 两边不是二选一，而是按任务类型分流——这也是作者自己在用的组合。
05

外挂与自动化

约 17:30 起

让 bot 从「你叫它才动」进阶到「自己按时开工」，靠三件东西：外挂（接外部服务）、Skills（现成的技能包）、Routines（定时 / 触发式例行任务）。

这一章的操作要点

  • 外挂：给 bot 接上外部工具和服务，扩大它能碰的东西。
  • Skills：给 bot 装技能包，某类活直接按成熟的方法做，不用你从头教。
  • Routines：直接在对话里跟 bot 说清楚「什么时候、做什么」，它就会按时或按触发条件自己执行——比如每天早上汇总情报、每周看一遍邮箱和日历给建议。
  • 另外还提到群组聊天：把多只 bot 拉进同一个对话里协作。
06

权限安全与心得

约 22:30 起

最后一章讲放心用的前提：权限要分清「读取」和「动手」，敏感凭据放进 Vault 保险箱。作者的原则很明确——让 bot 多读、多懂你，但真正对外产生后果的动作要锁住。

读取 Read — 可以放开

  • 读 Gmail、Google Calendar、Drive
  • 读得越多，bot 越懂你的背景和习惯，建议越准

动手 Act — 默认锁住

  • 寄信、发文、删档这类会产生实际后果的动作
  • 账号密码等敏感凭据存进 Vault 保险箱，不明文交给 bot
  • 作者的最终分工建议：Grok Bot 当你的 Personal Agent 主力，管日常、管团队、管自动化；真要写代码，再用远程控制把 Claude Code / Codex 接进来。

补充：照着视频顺序的上手路线

把六章压成一条可执行路径，第一次用 Grok Bot 时照这个顺序走即可。

  1. 下载安装，进主画面先熟悉三栏：左边 bot 列表、中间对话、右边 bot 的 Details / Library / Computer。
  2. 建第一只 bot，从一件具体的活开始别先建「万能助理」，先建一个职位明确的 bot（如设计负责人），在对话里派一件小事，确认它能交付。
  3. 给它补齐 Context写清岗位职责和要长期记住的背景，这是它后面所有判断的依据。
  4. 接 Integrations，先只开读取连 Gmail、Google Calendar 先让它读；寄信、删档等「动手」权限保持锁定。
  5. 设一位幕僚长，开始组队把重复出现的活拆给专职 bot，你只跟幕僚长对话、看汇总。
  6. 给例行活排 Routines每天 / 每周固定要做的事，直接在对话里交代时间和内容，让它自己开工。
  7. 敏感信息进 Vault，定期回看权限凭据只存保险箱；隔一段时间检查每只 bot 的读取 / 动手权限有没有给多。
  8. 写代码的活单独接 Claude Code / Codex用 remote control 遥控本地的编码工具开 PR，和 Grok Bot 的日常工作流并行。

看视频时容易漏掉的一点

视频中段（约 7:31）专门区分了「杂事」和「目标」两种交办方式：杂事是一件件派活，目标是给一个方向让幕僚长自己拆解推进。团队用法跑顺之后，尽量用「给目标」的方式交代，人才不用天天当传话筒——这也是幕僚长这个角色存在的意义。

名词速查

Bot
一只 AI 员工：有自己的职位、记忆、资料库和一台云端电脑，在对话里接任务、交结果。
幕僚长 Chief of Staff
团队的总管 bot。你把目标交给它，它负责拆解任务、分派给专职 bot 并汇总回报。
Context
bot 的指令与长期记忆：岗位说明、背景信息、偏好，都写在这里。
Integrations（外挂接入）
把 Gmail、Google Calendar 等外部服务接给 bot，让它能读信息、用工具。
Skills
可安装的技能包，给 bot 补上某类工作的成熟做法。
Routines
例行任务排班：到固定时间或满足触发条件，bot 自己开工。
云端电脑 Computer
每只 bot 的专属云端运行环境，24 小时在线，可保存账号登录状态；你关机它不停。
Vault 保险箱
存放账号密码等敏感凭据的安全区，配合权限设置使用。
群组聊天
把多只 bot 拉进同一个对话协作，适合需要几个专职 bot 配合的任务。
